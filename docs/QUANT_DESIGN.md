# Rushd Quant — Design Sub-Contract

Binding sub-contract under `docs/SYSTEM_DESIGN.md` (see parent DR-10, DR-11). Agents receive 2–5 line quotes as their DESIGN CONTRACT; every sentence here is load-bearing. This document governs the `src/quant/` module only; where it is silent, the parent contract governs and is not overridden. Decisions are final unless a Decision Record's "Revisit when" trigger fires. No contradiction with `prisma/schema.prisma` as it exists today is permitted — all new models live in §4 and are tagged to a Q-milestone.

**Inherited invariants (non-negotiable, from the parent contract):**
- **Mock-first, all milestones.** The entire committee, broker, and data spine run with zero external API keys (mock model, mock bars, `InternalSimBroker`). An exit criterion that only passes with keys is invalid. This holds through Q7 — there is no milestone at which mock mode is retired; live keys only *swap* an adapter (parent DR-4).
- **Money is `Decimal`.** Every money/quantity field is `Decimal @db.Decimal(18,4)` (money) or `Decimal @db.Decimal(18,6)` (shares/qty); no JS float arithmetic on money (parent DR-2).
- **Authz boundary.** Every quant read/write is scoped by the `src/lib/authz.ts` guard: a user sees only their own strategies, decisions, and portfolios; PARENT additionally sees their children's (parent DR-9 / §8).
- **Arabic-first.** Every user-facing rationale/label lands in `messages/en.json` + `messages/ar.json` key-identical; Arabic is Modern Standard Arabic, financial-literacy register (parent DR-6).
- **Not real money / not advice.** All execution is virtual play-money; global disclaimers apply to every quant surface.

## 1. Context & goals

**Product.** "Rushd Quant" is a committee of eight AI analyst agents that researches, debates, decides, and executes *simulated* trades on TASI and NASDAQ, shipped as an extractable `src/quant/` module inside the RUSHD monolith. It serves two purposes at once: (a) a **decision engine** that runs paper-money portfolios inside a deterministic risk-and-Sharia envelope; (b) the **flagship learning surface** — the learner watches the committee reason, watches the bull/bear debate, and watches the Sharia agent veto.

**Personas.**
- **Primary — self-directed learner, 18–40.** Owns an adult account (real email + password, existing PARENT credential shape or a future SELF role; v1 uses PARENT). Runs the committee on symbols, reviews decisions, approves or automates paper trades. This is the persona the committee UI (§10, Q7) is designed for.
- **Secondary — CHILD (~8–17), read-only watcher.** A child watches the committee as a tutor (rationale + debate + veto), earning XP through `addXP`; a child never approves or automates an order. Enforced by the authz guard, not UI branching.
- **Secondary — PARENT supervisor.** Gates a child's access to the committee by tier and sees the child's paper portfolio.

**Markets.** TASI is the quality bar (numeric symbols `2222`=Aramco/`1120`=Al Rajhi, SAR pegged 3.75/USD, trades **Sunday–Thursday** ~10:00–15:00 AST — never hardcode Mon–Fri). NASDAQ is secondary (alphabetic symbols, USD). Cadence is **daily bars** (end-of-day), not intraday.

**Market asymmetry.** NASDAQ gets real data + real paper-order execution + news through Alpaca. TASI gets real data (via a TASI vendor) but **internal-simulated execution** — no Gulf paper-broker exists to hit. A single `BrokerAdapter` interface (§5) abstracts both, so the committee code is broker-agnostic.

**Paper-first.** All execution is virtual: NASDAQ through the Alpaca **Paper** Trading API (real order lifecycle on virtual money), TASI through `InternalSimBroker`. Because Alpaca paper and live share one API, paper→live is a keys + base-URL swap that is **hard-gated** dark until CMA licensing (QDR-2). No real funds move in any Q-track milestone.

**Tier gating.** HUMAN_APPROVE mode is available to PREMIUM+; AUTO_PAPER (committee auto-executes paper orders) is ULTRA-only; AUTO_REAL is dark for everyone (QDR-2, §7). Gating is enforced in the authz helper, server-side.

**What "done" means for the Q-track (through Q7).**
1. A point-in-time (PIT) data spine (`MarketBar`/`Fundamentals`/`NewsItem`) is populated from Alpaca + a TASI vendor, mock-first.
2. The 8-agent committee runs a full pass on a symbol and persists every `AnalystSignal`, the debate transcript, and the final `Decision` for audit and replay.
3. The Sharia agent's hard veto and the Risk Manager's caps are enforced **deterministically and identically live vs backtest**.
4. Paper orders execute through `BrokerAdapter`; positions, virtual cash, and cost-basis are tracked per strategy.
5. A backtest engine runs walk-forward with out-of-sample holdout and Deflated-Sharpe validation, using a **deterministic PM policy-surrogate**.
6. A bilingual committee-reasoning UI shows the eight agents, the debate, and the veto.
7. Every one of the above works with **zero API keys**.

**Non-goals (Q-track).** Real brokerage / live money (QDR-2, dark), options/derivatives/leverage, intraday or high-frequency trading, Python/ML rewrites (QDR-3), multi-user fund pooling, tax-lot accounting beyond average cost-basis.

## 2. Committee architecture

### 2.1 The `AnalystSignal` contract

The seven analyst agents emit one shape; the PM consumes seven of them plus the debate. Every field is auditable and persisted (`AnalystSignalRecord`, §4).

```ts
type AgentKind =
  | 'QUANT_CORE' | 'NEWS_CATALYST' | 'TECHNICAL' | 'PATTERN_ANALOG'
  | 'SHARIA' | 'FUNDAMENTAL' | 'RESEARCH' | 'PORTFOLIO_MANAGER';

type Stance = 'BULLISH' | 'BEARISH' | 'NEUTRAL';

interface Evidence {           // one auditable feature or citation
  kind: 'feature' | 'citation' | 'ratio' | 'headline' | 'analog';
  ref: string;                 // e.g. 'RSI(14)', 'filing:2222/Q1-2026', 'doc:momentum-92'
  value: string;               // stringified so it survives JSON persistence
}

interface AnalystSignal {
  agent: AgentKind;
  symbol: string;
  market: 'TASI' | 'NASDAQ';
  asOf: Date;                  // the PIT cutoff the signal was computed at
  stance: Stance;
  conviction: number;          // 0..1
  horizonDays: number;         // intended holding horizon
  rationaleEn: string;
  rationaleAr: string;         // Arabic-first (parent DR-6); MSA, non-empty
  evidence: Evidence[];        // never empty for a non-abstaining signal
  determinism: 'deterministic' | 'llm';   // reproducibility class
  modelId?: string;            // set iff determinism === 'llm'
  failureMode: 'ok' | 'degraded' | 'abstain';
  costCents: number;           // LLM spend (0 for deterministic agents)
}
```

### 2.2 The `Analyst` interface and the `PointInTimeContext` (no look-ahead)

```ts
interface Analyst {
  agent: AgentKind;
  run(ctx: PointInTimeContext): Promise<AnalystSignal>;
}

interface PointInTimeContext {
  symbol: string;
  market: 'TASI' | 'NASDAQ';
  asOf: Date;                                   // HARD cutoff; nothing after asOf is visible
  bars(lookbackDays: number): MarketBar[];      // bars with ts <= asOf only
  fundamentals(): Fundamentals | null;          // latest filing with filedAt <= asOf
  news(sinceDays: number): NewsItem[];          // publishedAt in (asOf - since, asOf]
  shariaVerdict(): ShariaVerdict;               // screening as-of asOf
  portfolio(): PortfolioSnapshot;               // holdings + virtual cash at asOf
}
```

`PointInTimeContext` is the **only** data door. An agent must never call `marketData.ts`, a live fetch, or the DB directly — it reads exclusively through `ctx`. In a backtest, `asOf` sweeps historical dates; live, `asOf = now`. Because every filter (`ts`/`filedAt`/`publishedAt <= asOf`) is applied inside `ctx`, the same agent code is **byte-identical** between live and backtest — this is the no-look-ahead guarantee (§6).

### 2.3 The eight agent contracts

| # | Agent | Kind | Inputs (via `ctx`) | Output | Failure mode |
|---|---|---|---|---|---|
| 1 | **Quant Core** | deterministic TS | `bars(252)` | Composite factor score → `AnalystSignal`. Features: 12-1 momentum, realized volatility, mean-reversion z-score, MA(50/200) trend, volume trend. | `<60` bars → `abstain`. |
| 2 | **News/Catalyst** | LLM (cheap, temp 0) + feed | `news(7)`, `bars(5)` | LLM classifies catalyst type + sentiment + materiality → stance = sign(sentiment)·materiality. | No news → `NEUTRAL`, conviction 0. LLM error / no key → mock signal, `degraded`. |
| 3 | **Technical/Chart** | deterministic TS | `bars(120)` | RSI(14), MACD, Bollinger position, support/resistance, deterministic candlestick-pattern set → stance. | `<30` bars → `abstain`. |
| 4 | **Pattern/Analog** | data-mining TS (strictly validated) | full history via `ctx.bars` | kNN over normalized recent-return shape → forward-return distribution of historical analogs → stance + validity flag. | `< MIN_ANALOGS` (default 100) → `abstain`; **never fabricates**. Analog windows must not overlap the current lookback (leakage guard). |
| 5 | **Sharia** | deterministic TS — **HARD VETO** | `shariaVerdict()`, `fundamentals()` | AAOIFI two-stage screen (sector; interest-debt <30% mcap, interest-securities <30% mcap, non-compliant income <5%) → `ShariaGate { compliant, reason }`. **Not** a graded opinion — an absolute gate evaluated in the envelope (§2.5), not in the debate. | Screener unavailable → **fail-closed**: treat as non-compliant (veto any BUY/increase; SELL/HOLD allowed). Never fail-open. |
| 6 | **Fundamental** | LLM (cheap, temp 0) + structured | `fundamentals()`, `bars(252)` | Runs investor-persona lenses — **Sharia value-investor lens** (low leverage, real assets, purification), **Gulf/TASI persona** (dividend + local-sector context), growth, quality/margin — each scored via `generateObject`+zod; composite stance with per-lens breakdown in `evidence`. | No fundamentals → `abstain`. LLM error / no key → mock, `degraded`. |
| 7 | **Research/Literature** | LLM (temp 0) + RAG | `symbol`, sector, curated corpus (retrieval) | Retrieves relevant strategy/finance literature, grounds a stance with `citation` evidence refs. | Empty retrieval → `NEUTRAL`, conviction 0. Retrieval/LLM error → `abstain`. Ships Q4. |
| 8 | **Portfolio Manager** | LLM (**strong**, temp 0) — **decides** | the 7 signals + debate transcript + `portfolio()` + `RiskEnvelope` | Chooses `action` (BUY/SELL/HOLD) + `targetQty` via `generateObject`+zod. **The only agent that decides.** Emits a `ProposedDecision`, then passes through the deterministic envelope (§2.5). | LLM error / no key → deterministic fallback = **HOLD** (do nothing). |

### 2.4 The bull/bear debate (TradingAgents pattern)

Before the PM decides, two LLM debaters argue **bull** vs **bear** using the seven analyst signals as evidence, for `DEBATE_ROUNDS` (default 2, hard-capped at 3), temperature 0. The transcript is an input to the PM and is persisted verbatim on `Decision.debateTranscript`. The debate is **advisory** — it shapes the PM's reasoning but can never move the deterministic envelope. Debaters use the cheap model for rounds 1..n-1 and the strong model for the final round.

### 2.5 The decision hierarchy — "LLM decides inside a deterministic envelope it cannot cross"

The PM (an LLM at temp 0) chooses **action + size**; two deterministic gates bound it (the virattt/ai-hedge-fund hierarchy). The final decision is `clamp(envelope, PM proposal)`:

1. **Sharia gate (agent 5) — absolute veto.** If the symbol is non-compliant, any BUY or position-increase is rejected and forced to HOLD or SELL-to-flat. Deterministic; identical live vs backtest.
2. **Risk Manager — deterministic caps.** Clamps or rejects the PM's size against: max % NAV per symbol, sector + market exposure caps, gross-exposure cap, per-trade stop distance × size, a portfolio drawdown breaker (halt new BUYs beyond −X% peak-to-trough), and the kill-switch (§7). Not an LLM.
3. **Final `Decision`** persists full lineage: the seven `AnalystSignalRecord`s, the debate transcript, the PM's raw proposal, every envelope adjustment, and the final action — so the decision is replayable and auditable (§6).

```
7 analysts ──▶ bull/bear debate ──▶ PM (LLM, temp 0) proposes {action, qty}
                                          │
                              ┌───────────▼───────────┐
                              │  DETERMINISTIC ENVELOPE│
                              │  Sharia gate (veto)    │  ← identical live & backtest
                              │  Risk Manager (clamp)  │
                              └───────────┬───────────┘
                                          ▼
                              final Decision → Order (BrokerAdapter)
```

### 2.6 Model tiering and LLM-call budget

Runtime LLMs are explicit opt-in: only `QUANT_LLM_API_KEY` activates them; generic app/OpenAI keys never do. News uses a cheap free-tier model; Fundamental, Research, the bilateral debate, and PM use a stronger free-tier model. One structured debate call returns both Bull and Bear cases, so a full live pass is capped structurally at five primary calls (News + Fundamental + Research + bilateral debate + PM). A second free-model attempt is disabled by default and requires `QUANT_LLM_RETRY=true`. With no Quant key, all five stages use deterministic/local fallbacks; the PM reuses the versioned backtest surrogate proposal before the unchanged risk envelope and Sharia veto.

### 2.7 Execution model — no worker, no queue (QDR-5)

RUSHD is stateless on Render; there is no background worker or queue. A committee pass is therefore triggered exactly two ways, mirroring parent DR-8: (a) a **synchronous authenticated user action** (`POST /api/quant/run`, single symbol, returns the `Decision`); (b) a **signed cron batch pass** (`POST /api/quant/cron/run`, a universe, daily after close, idempotent per day). No `setInterval`, no BullMQ, no second service.

## 3. Prior art & learnings

- **TradingAgents (arXiv 2412.20138).** Adopted: the bull/bear debate round (§2.4) and deep/quick model tiering (§2.6). Designed-against caveats: its reported Sharpe of 5–8 is implausibly high — the hallmark of look-ahead, small-sample, or survivorship contamination, so we enforce the PIT context (§2.2), Deflated Sharpe, and an auto-flag on any Sharpe > 3 (§6); its agents are non-deterministic, so we pin temperature 0, persist every decision, and back-test with a policy-surrogate (QDR-4); it was never run live, matching our paper-first + CMA gate (QDR-2).
- **virattt/ai-hedge-fund.** Adopted: the PM-decides-inside-a-risk-constraint-hierarchy (§2.5) and investor-persona lenses (agent 6). Designed-against caveat: it is explicitly educational-only with no return validation — our walk-forward + Deflated-Sharpe science (§6) is the addition that makes any "validated" claim defensible.
- **Backtest-overfitting literature (Bailey & López de Prado; walk-forward analysis).** Adopted wholesale as Q2 guardrails: walk-forward windows, a contiguous out-of-sample holdout, the **Deflated Sharpe Ratio** correcting for the number of trials, a minimum backtest length / trade count, and a profit-plateau (parameter-robustness) check before any strategy is marked "validated" (§6).

```ts

  kind: 'ALPACA_PAPER' | 'INTERNAL_SIM';
```

## 6. Quant integrity guardrails

- **No look-ahead.** `PointInTimeContext` (§2.2) is the only data door; `asOf` is a hard cutoff; `ts`/`filedAt`/`publishedAt` are all filtered `<= asOf`; deterministic agents are byte-identical live vs backtest. `InternalSimBroker` fills next-bar-open, never same-bar-close.
- **Overfitting defense.** Walk-forward windows; a contiguous out-of-sample holdout of **≥20–30%** of the period, always the last slice; a minimum of **100–200 trades** before a strategy is marked "validated"; the **Deflated Sharpe Ratio** computed against the number of trials; a **profit-plateau** check (metrics stable under ±parameter perturbation); and an **auto-flag** on any `BacktestRun` with Sharpe > 3 (`implausible = true`) that **blocks auto-promotion** to an enabled strategy. The Pattern/Analog agent additionally requires `>= MIN_ANALOGS` or it abstains.
- **Fill realism.** `InternalSimBroker` applies commission (bps), slippage (bps scaled by realized volatility / half-spread), and a **liquidity cap** — an order exceeding `MAX_BAR_VOLUME_PCT` of the bar's volume fills partially. Alpaca paper provides real fills.
- **Survivorship.** The `MarketBar` spine retains delisted symbols; a backtest universe is the **as-of** constituent set, never today's survivors.
- **Risk management (deterministic, in the envelope §2.5).** Position cap (% NAV/symbol), sector + market exposure caps, gross-exposure cap, per-trade stop (max loss %), a **portfolio drawdown breaker** (halt new BUYs beyond −X% peak-to-trough), and a **kill-switch** (§7).
- **Reproducibility.** Every `Decision` persists `pmModelId`, `temperature (0)`, `seed`, `gitSha`, `asOf`, and the full input signal set → replay reproduces the deterministic envelope exactly. Backtests use a deterministic **policy-surrogate** for the PM (QDR-4) and spot-check that the live LLM agrees; `BacktestRun` records `seed` + `gitSha`.
- **Mock-first invariant.** The committee, broker, and spine run end-to-end with zero keys (mock model, mock bars, `InternalSimBroker`). Inherited from the parent contract; holds through Q7.
- **Monte Carlo gate (deterministic lane).** The intraday strategy lane adds Monte Carlo validation as a promotion gate co-equal with Deflated Sharpe and extends the implausible flag to any claimed daily return ≥3σ of validated history — see QDR-6.

## 7. Autonomy tiers, kill-switch, regulatory gate

**Autonomy tiers (`Decision.mode`).**
- **HUMAN_APPROVE** (PREMIUM+, default for everyone) — the committee proposes; a human clicks approve; then the order submits.
- **AUTO_PAPER** (ULTRA only) — the committee auto-submits **paper** orders inside the envelope, no click; the user is notified and can review the next pass. Gated in the authz helper by tier, server-side.
- **AUTO_REAL** (dark) — auto-submits **real** orders. Requires `QUANT_LIVE_EXECUTION=1` + a CMA-license record + per-user KYC. Off in every environment until CMA licensing (QDR-2). No UI path exists in the Q-track.

**Kill-switch.** `submitOrder` checks, **before any broker call**, both `QUANT_KILL_SWITCH` (env) and `QuantControl.halted` (DB, §4). Either set → the submission is rejected deterministically. The drawdown breaker (§6) flips `QuantControl.halted` for a runaway strategy automatically.

**Regulatory gate.** Paper-only simulation needs no securities license (virtual money, matching the parent's play-money SAMA posture, DR-9). Live execution needs a **CMA license + KYC**, is isolated in `src/quant/execution/` behind `assertLiveExecutionAllowed()`, and is dark by default. This is the new DR-11 boundary in the parent contract.

## 8. Decision records

### QDR-1: The PM (LLM, temp 0) decides action and size inside a deterministic Sharia + risk envelope it cannot cross
Decision: the Portfolio-Manager LLM chooses BUY/SELL/HOLD + target size at temperature 0, and the final decision is `clamp(envelope, proposal)` where the Sharia agent is an absolute deterministic veto and a deterministic Risk Manager clamps size/exposure/drawdown — the LLM can never exceed either.
Options: rules-only decisions (deterministic but no adaptive reasoning, defeats the "committee" product) / LLM-only decisions (non-reproducible, un-auditable, cannot guarantee Sharia compliance or risk caps) / LLM-decides-inside-deterministic-envelope (virattt hierarchy — adaptive reasoning bounded by hard, replayable gates).
Rationale: the product needs an LLM's judgment as the flagship learning surface, but Sharia compliance and risk limits are non-negotiable and must be identical live vs backtest — only a deterministic envelope delivers both, and it makes every decision replayable.
Consequences: the Sharia gate and Risk Manager are pure TS (no LLM), evaluated after the PM; the PM's raw proposal and every clamp are persisted on `Decision`; a non-compliant symbol can only ever HOLD or SELL-to-flat.
Revisit when: a Sharia board approves a graded (non-binary) compliance treatment, or risk caps need per-user personalization beyond static config.

### QDR-2: Paper-first execution through a `BrokerAdapter`; real execution is dark and gated behind CMA licensing
Decision: all execution is virtual — Alpaca Paper for NASDAQ, `InternalSimBroker` for TASI — behind one `BrokerAdapter`; the live broker is one base-URL swap away but stays dark behind `assertLiveExecutionAllowed()` (flag + CMA license + KYC), isolated in `src/quant/execution/`.
Options: build real execution now (needs a CMA license, KYC/AML, and PSP rails RUSHD does not have) / paper-only with no live path (throws away the paper→live design symmetry Alpaca gives us) / paper-first behind an adapter with a dark, hard-gated live path (legal today, one-swap-later, testable end-to-end with mocks).
Rationale: Alpaca's paper and live APIs are identical, so a `BrokerAdapter` lets us build and validate the entire order lifecycle on virtual money now and flip to live only when licensed — with no rewrite. TASI has no paper broker, so `InternalSimBroker` is required regardless.
Consequences: the whole committee is exercisable with zero keys; a single guard function is the entire legal blast radius for going live; TASI and NASDAQ share one execution interface despite the market asymmetry.
Revisit when: a CMA license is obtained and a real-deposit pilot is approved — then `AlpacaLiveBroker` + KYC + DB-session revocation (parent OQ-5) land together.

### QDR-3: TypeScript-first, extractable `src/quant/` module; Python only if ML outgrows TS
Decision: build the entire committee in TypeScript under a self-contained `src/quant/` directory with a clean seam (the `Analyst`/`BrokerAdapter`/`PointInTimeContext` interfaces), and defer any Python/ML rewrite until modeling demonstrably outgrows TS.
Options: Python service now (a second runtime + IPC + deploy target for signals that are today deterministic indicators and LLM calls — infra RUSHD's scale cannot justify) / TS embedded across the app with no module boundary (un-extractable, couples quant to UI) / TS-first in an isolated `src/quant/` module (one language, one deploy, extractable later at a defined seam).
Rationale: the current agents are deterministic indicators plus OpenAI-compatible LLM calls — all first-class in TS and already in the stack (`ai`+`zod`); a separate Python service adds a queue, an API, and a deploy for zero present benefit (lazy-dev rung: reuse the monolith). The module boundary makes a future extraction a lift-and-shift, not a rewrite.
Consequences: no new runtime or deploy target in the Q-track; heavy numeric/ML work (if it arrives) is confined behind the `Analyst` interface and can be reimplemented per-agent in Python without touching the committee wiring.
Revisit when: an agent needs training/inference libraries with no viable TS equivalent (e.g. gradient-boosted models on large panels) — extract that agent alone behind its interface.

### QDR-4: Backtests use a deterministic PM policy-surrogate with live-LLM spot-checks; Sharia veto and risk caps are identical live vs backtest
Decision: the backtest engine replaces the live PM LLM with a **deterministic policy-surrogate** (a rules function distilled from PM behavior) so a run is fully reproducible, and periodically spot-checks that the live PM agrees on sampled dates; the Sharia gate and Risk Manager are the same deterministic code in both paths.
Options: call the live LLM at every backtest step (non-deterministic, un-reproducible, and thousands of paid calls per run) / cache LLM outputs per date (brittle, invalidated by any prompt change, still non-deterministic on cache miss) / deterministic policy-surrogate + spot-check (reproducible, cheap, and the deterministic gates already run identically).
Rationale: a backtest whose result changes between runs is worthless for validation (this is exactly the TradingAgents non-determinism caveat, §3); the surrogate makes metrics reproducible under `seed`+`gitSha`, while spot-checks keep it honest to the live PM. The gates that actually matter for compliance and risk are deterministic in both paths by construction.
Consequences: the surrogate must be maintained alongside PM-prompt changes (spot-check divergence flags drift); `BacktestRun` records `seed`+`gitSha` for exact replay; live and backtest can differ only in the PM's graded proposal, never in Sharia or risk outcomes.
Revisit when: spot-check agreement between surrogate and live PM falls below a set threshold, forcing a surrogate re-fit.

### QDR-5: The committee runs as synchronous user actions and signed-cron batch passes — no worker, no queue
Decision: trigger committee passes only two ways — a synchronous authenticated `POST /api/quant/run` (single symbol) and a signed, per-day-idempotent `POST /api/quant/cron/run` (universe batch, after close) — reusing parent DR-8's Render-cron pattern; add no worker, queue, or second service.
Options: in-process scheduler (`setInterval` dies with the stateless request lifecycle on Render) / a worker + queue (BullMQ/Redis — new infra for a daily batch) / synchronous route + Render cron → signed internal route (reuses what we already deploy).
Rationale: a daily batch over a bounded universe plus on-demand single-symbol runs needs neither a queue nor a second runtime; the parent already runs Render cron against a signed route, so we extend it. Order submission must be **idempotent and atomic** — the batch wraps each symbol's decide-and-submit in a `prisma.$transaction` and relies on `Order.@@unique([decisionId])`, explicitly avoiding the non-atomic per-row race present in the Mudarabah cron.
Consequences: no retry infrastructure — a missed batch is caught by the next day's idempotent pass; long universes must fit inside the route's execution budget (chunk if needed, still no queue); per-instance in-memory limiters are advisory, DB idempotency is authoritative.
Revisit when: the universe grows past what one request can process within the platform timeout, or intraday cadence is required — then introduce one worker + a lightweight queue (couples with parent DR-8's trigger).

### QDR-6: Deterministic intraday strategy lane (gapper momentum) with Monte Carlo validation as a first-class gate
Decision: add an **LLM-free strategy lane** to `src/quant/` — versioned, deterministic `StrategySetup` rules (screen/entry/exit, PIT-only) that emit `AnalystSignal`-compatible output into the **unchanged** downstream envelope + Sharia gate — starting with a small-cap **gapper momentum** setup, **NASDAQ-only first**, **long-only cash** (no short, no margin — Sharia). It runs on a new 1-minute intraday spine: `IntradayBar` (1-min bars incl. premarket) + `SymbolSnapshot` (mcap, float?, premarket %, cumulative volume), PIT-safe through the `pointInTime.ts` patterns (§2.2). Screener parameters are a **versioned config, never hardcoded**; v1 defaults: `mcapMin=10e6`, `mcapMax=400e6`, `premarketMovePct>=5`, `dayMovePct>=5`, `minCumVolume=10e6` shares. Data comes in three tiers: **bundled fixtures of captured real market data** (real downloaded bars snapshotted into the repo for keyless/CI determinism — **synthetic/generated bars are prohibited** in this lane's data and validation numbers) → **Alpaca free-key historical backfill** (resumable, 90-day initial then incremental) → **Yahoo keyless short-history** (always labeled as short-history). The intraday snapshot path **bypasses the 12h universe cache**; the 24h Sharia verdict cache stays. **Monte Carlo validation is a promotion gate co-equal with Deflated Sharpe** (§6).
Options: extend the LLM committee to intraday cadence (impossible under the 5-call FREE_MODE budget §2.6, non-reproducible per-minute, and QDR-5 forbids the worker it would need) / a standalone gapper script outside `src/quant/` (no PIT guarantee, bypasses the envelope and Sharia gate, unauditable) / a deterministic `StrategySetup` lane inside the module, reusing `AnalystSignal` + envelope, with Monte Carlo promotion gates (reproducible, Sharia-gated, zero LLM calls, extensible to a setup catalog).
Rationale: intraday cadence rules out LLM calls entirely, and deterministic rules are the only replayable, budget-free path; emitting `AnalystSignal`-compatible output means the Sharia veto and risk clamps are byte-identical live vs backtest with no new gate code (QDR-1, QDR-4). Gapper-style strategies produce few, fat-tailed trades where a single realized equity curve overfits notoriously — bootstrap and permutation tests measure the *distribution* of outcomes, which is the only honest basis for promotion or user-facing claims.
Consequences:
- **MC gate** (`monteCarlo.ts`): trade-outcome bootstrap (equity-curve distribution, maxDD percentiles, risk-of-ruin), an entry-jitter permutation test, and fractional-Kelly sizing **clamped by the envelope**.
- **Promotion checklist (all required):** walk-forward + ≥20–30% OOS holdout + ≥100–200 trades + Deflated Sharpe + profit plateau (§6) **and** MC maxDD p95 within the envelope's drawdown breaker.
- **Portfolio-valid validation seam:** any strategy claiming basket-vol, shared-cash, gross-exposure, drawdown, or position-count control MUST run through one deterministic, DB-free, monolith-internal daily strategy-book engine. The engine iterates date-major, owns one shared cash/NAV/positions state per strategy version, passes those real positions to `applyEnvelope`, and emits the true daily NAV/drawdown series. Same-day entry priority is canonical symbol ascending order, frozen before OOS and never selected from results. Legacy independent per-symbol simulation and pooled-exit reporting remain byte-stable for reproducibility, but they cannot validate portfolio-level controls and are used only when the CLI explicitly stays on the legacy route.
- **Honest-expectations policy:** the deliverable is the **measured daily-return distribution**, incl. `P(day ≥ +5%)` and `P(day ≤ −5%)`; no promised returns anywhere in copy; the §6 implausible flag **extends to any claimed daily return ≥3σ of validated history**.
- **Automation:** AUTO_PAPER only (ULTRA, §7), via **premarket + intraday signed-cron passes** — QDR-5's cron pattern over a bounded screener universe, still no worker and no queue. On pass error, a surrogate-trade fallback is acceptable for AUTO_PAPER but **MUST revert to fail-safe HOLD as a precondition of any future AUTO_REAL enablement** (QDR-2 gate).
- §1's intraday non-goal is **narrowed, not removed**: no intraday LLM committee and no HFT; deterministic minute-bar setups are in scope via this lane only. New additive models `IntradayBar`/`SymbolSnapshot` follow §4's rules and are tagged to G1 (§9b).
Revisit when: TASI intraday data becomes viable (extend the lane, same rules), a proposed setup requires shorting (out absent a Sharia-board ruling), or the MC and Deflated-Sharpe gates persistently disagree on promotions — then re-weight the gate composition.

### QDR-7: Competing books — multi-mode capital-allocation tournament (paper)
Decision: run every ACCEPTED strategy mode as a **competing team** — binding user directive, verbatim: *"the modes will act like different teams, that compete to achive its own goal while shria complince ofcurse"* [sic] — where each mode runs an **isolated virtual book** (its own virtual NAV, positions, and P&L) in the **AUTO_PAPER lane only (ULTRA, §7)**, and tournament capital is divided by a **deterministic, seeded capital allocator** that runs as a step **inside the existing signed cron passes** (QDR-5 — no worker, no queue, no second service). Entry to the league is **only** via QDR-6's promotion gates (walk-forward + OOS holdout + Deflated Sharpe + **Monte Carlo validation as a promotion gate co-equal with Deflated Sharpe** + profit plateau); the binding lifecycle is `CANDIDATE → CODIFIED → VALIDATING → ACCEPTED | REJECTED`, and the roster lives in `docs/STRATEGY_LAB.md`. The allocator re-scores **monthly** on a **rolling ~63-trading-day live-paper window blended with validation-card priors** (the mode's `BacktestRun` card metrics) via **shrinkage**, so a small live N can never swamp accepted evidence; the score is **deflated-Sharpe-style with an explicit drawdown penalty**. Hard caps: **no mode may hold >40% of tournament capital**; **bench = 0% is allowed**; a **drawdown-breaker breach benches the mode immediately, mid-cycle**, without waiting for the monthly re-score. The tournament is **paper-only**; AUTO_REAL is unchanged and stays dark behind QDR-2's CMA gate.
Options: one merged book for all modes (no per-mode attribution — one mode's drawdown masks another's edge, and "compete to achieve its own goal" is unmeasurable) / static equal-weight split (ignores live evidence entirely; no competition, just co-existence) / an ML meta-allocator or a separate allocator service (non-reproducible scoring, and a second service/queue that QDR-5 forbids at this scale) / a deterministic seeded shrinkage allocator over isolated virtual books inside the existing cron passes (replayable, evidence-weighted, zero new infra — chosen).
Rationale: isolated books are the only honest basis for attribution — each team pursues its own declared goal and is scored on its own realized paper P&L; the shrinkage blend toward validation-card priors is the same honesty posture as §6 and QDR-6 (small live samples are noisy, validated evidence anchors the score); a seeded deterministic allocator keeps every allocation replayable under §6's reproducibility rule; and the whole mechanism reuses what exists — the AUTO_PAPER lane, `AutoRunClaim` idempotency, the `QuantControl` kill-switch, the `Decimal` risk envelope, the pre-envelope Sharia hard veto, `PurificationEntry`, and `BacktestRun` cards — so the tournament costs one additive model and one cron step (lazy-dev: use what exists).
Consequences:
- **Validation finalization is binary and version-scoped.** `CANDIDATE`, `CODIFIED`, and `VALIDATING` are the only nonterminal validation states. Every completed or abandoned validation run ends as exactly **ACCEPTED** or **REJECTED**; `INSUFFICIENT_TRADES`, `PARKED`, and `FAILED_PROMOTION` are never terminal statuses. **ACCEPTED means admission of that exact strategy/parameter version to the AUTO_PAPER league only**; it is neither a profit promise nor permission for AUTO_REAL. **REJECTED applies to that exact version/test run**, not the hypothesis forever; a revised version re-enters at `CANDIDATE` and must pass every gate on fresh evidence. Only ACCEPTED versions receive a book or allocation.
- **A terminal evidence card is mandatory.** Finalization is invalid until `docs/STRATEGY_LAB.md` records: strategy id + parameter version; ACCEPTED/REJECTED; ordered rejection reason codes (empty only for ACCEPTED); tested period, cadence, universe, data feed and data-quality/PIT caveats; explicit in-sample and OOS results; total and OOS trade counts; CAGR or cadence-appropriate return, Deflated Sharpe, max drawdown, Calmar, hit rate, average win/loss or expectancy, turnover and exposure (use `n/a — not persisted` rather than inventing); MC p95 max drawdown, `P(day≥+5%)`, `P(day≤−5%)`, risk of ruin and permutation p-value; profit-plateau and implausibility flags; Sharia compliance state + instrument charter; and reproducibility identifiers (strategy/params version, seed, git SHA, `BacktestRun` id and result path). IS and OOS numbers must never be blended. A return without drawdown and trade count is not a result card.
- **Rejection reason codes are deterministic and cumulative.** Record every triggered code in this fixed order: `INSUFFICIENT_SAMPLE` (trade count below the versioned minimum; default statistical floor 100), `OOS_FAILURE` (the versioned OOS gate fails, including non-positive OOS return/CAGR or expectancy), `DSR_FAILURE` (the Deflated-Sharpe promotion gate is false), `DRAWDOWN_RISK_FAILURE` (MC p95 max drawdown exceeds the envelope breaker or risk of ruin exceeds its versioned limit), `IMPLAUSIBLE_RESULT` (§6/QDR-6 flag is true), `NO_PROFIT_PLATEAU_OVERFIT` (profit-plateau gate is false), `SHARIA_NON_COMPLIANT` (charter or PIT verdict forbids the instrument), `SHARIA_UNVERIFIABLE` (compliance cannot be verified for executable entry), `DATA_QUALITY_PIT_FAILURE` (required real/PIT data is missing, contaminated, or look-ahead/survivorship integrity fails), and `REPRODUCIBILITY_FAILURE` (seed/version/git SHA/run artifact missing or deterministic replay differs). Unscreened research may be measured, but it is execution-blocked and cannot be ACCEPTED; the evidence card must say `UNSCREENED` and carry `SHARIA_UNVERIFIABLE`. A Sharia hard-veto result carries `NON_COMPLIANT` and `SHARIA_NON_COMPLIANT`.
- **Sharia is the league constitution, not a per-team policy.** Every team's every signal passes the existing **per-signal Sharia hard veto ahead of the risk envelope** — no mode can trade around it. Each mode additionally declares a **per-mode instrument charter** (its permitted instrument/universe class, versioned in its config). Contested instruments remain `CANDIDATE — WAITING_SHARIA_REVIEW`: no validation finalization, trading, or score contribution until fiqh adjudication. **Sharia-unscreened universes may be evaluated only as execution-blocked research per parent DR-5** (e.g. until screened via Zoya); they cannot be ACCEPTED or join AUTO_PAPER. **Purification is computed per book** through `PurificationEntry`, so each team's purification obligation is separately auditable.
- **Discipline bounds.** Each mode carries a **live-vs-backtest tracking-error bound**; a breach triggers **immediate auto-bench + mandatory re-validation** through the QDR-6 gates before re-entry. Any mode whose latest run carries the §6/QDR-6 **implausible flag is disqualified from allocation** until the flag is cleared by a clean validated run.
- **Auditable allocation persistence.** New additive model **`AllocationDecision`**: `asOf DateTime`, `windowDays Int` (default 63), `seed Int`, `gitSha`, `inputs Json` (per-mode live-window metrics + validation-card priors + shrinkage weights), `scores Json`, `allocations Json` (mode → weight, Decimal-string), `benched String[]`, `reason String?`, `createdAt`; `@@unique([asOf])` gives monthly idempotency. Follows §4's rules (additive, `Decimal` money math, no existing model altered) and is tagged to roadmap row **G7 (§9b)**.
- **No new infra.** The allocator runs inside the existing signed cron passes (QDR-5); `AutoRunClaim` idempotency and `QuantControl.halted` apply unchanged; all book NAV/weight math is `Decimal`.
- **Shared within a mode, isolated across modes.** A multi-symbol mode uses QDR-6's shared-cash daily strategy-book engine for its own holdings and NAV; no cash, position, or P&L crosses into another mode's isolated book.
- **UI.** The league table is post-pause **G5 scope** (the `/quant` strategy tab), with every figure labeled **simulated/paper** under §6's honest-expectations policy — standings, not promised returns.
Revisit when: a CMA license opens QDR-2's gate (a real-capital allocation policy must be designed separately before any tournament output ever feeds AUTO_REAL); the validated-mode count pushes the monthly re-score past one cron pass's execution budget (chunk per QDR-5 before any worker/queue discussion); or a fiqh adjudication resolves the parked-instrument set in a way that changes the charter model.

### QDR-9: Two-tier DSR trial deflation (exploratory vs confirmatory) + a mandatory seal-time feasibility and power assertion
Decision: DSR trial deflation becomes **two-tier**, and a preregistration whose acceptance set is provably empty or provably underpowered is **refused at seal time**. (a) **EXPLORATORY is the fail-closed default** and is byte-identical to today's behavior: any evaluation whose setup was selected, compared, or tuned against previously-observed results, or that received **any** historical or diagnostic inspection, carries the registered family trial floor from `src/quant/backtest/trialFamilies.ts` (currently `HALAL_CORE_REGISTERED_TRIALS = 99`, or 108 where a manifest already sealed that count). (b) **CONFIRMATORY sets trial count N = 1** — a multiple-testing correction deflates for **selection**; a sealed, preregistered, never-inspected forward test performs no selection, so N = 1 is the statistically correct count, **not** a relaxation (this is the exploratory/confirmatory split of clinical-trial practice, and `deflatedSharpe` in `src/quant/backtest/metrics.ts` already reduces to the plain PSR at N ≤ 1 with no code change to the estimator). (c) CONFIRMATORY status is **earned structurally, never self-asserted**, and fails closed to EXPLORATORY if any of six conditions is unproven (below). (d) At seal time a preregistration must pass a **feasibility assertion** (its acceptance set is non-empty at the Sharpe = 3.00 implausibility ceiling) **and** a **power assertion** (its declared hypothesized effect size clears the gate inside the reserved window). This amends QDR-6's promotion checklist and QDR-7's `DSR_FAILURE` semantics **only in the trial-count input**; it introduces no new terminal rejection reason code, so QDR-7's fixed ordered code list stays byte-identical.
Options: (i) keep the 108-trial family deflation and simply extend the reserved forward window — at 99–108 trials the required annualized Sharpe is 3.13 at 2 years, 2.42 at 3, 1.87 at 5 and 1.32 at 10, so the first structurally possible ACCEPTED lands around 2034 and every setup added in the meantime pushes it further out (rejected: it converts preregistration into a decade-long unfalsifiable wait, and the deflation it preserves is a correction for selection that a sealed forward test does not perform) / (ii) count distinct hypotheses (11–12) instead of plateau variants (rejected: it is an unprincipled halfway measure — it still deflates a no-selection forward test, it re-opens the count to per-run argument exactly where the registry exists to remove argument, and it inherits the same monotone tightening as new setups land) / (iii) leave the gate untouched and reframe the whole program as falsification-only, with ACCEPTED formally unreachable (rejected: honest but self-defeating — QDR-7's allocator and QDR-8's promotion path v2 both terminate in an ACCEPTED state, and a gate that can never be passed provides no evidence, only a ratchet) / (iv) the two-tier exploratory/confirmatory split with a seal-time feasibility+power assertion (chosen: it corrects the count only where no selection provably occurred, leaves every threshold and every exploratory result untouched, and moves the empty-acceptance-set failure from two years after sealing to the seal itself).

- **Seal-time feasibility assertion (refusal, not a warning).** With `SRp = sharpeCeiling / sqrt(periodsPerYear)` (sharpeCeiling = 3.00, the implausibility flag), `n` = the preregistered observation count, and `C = (1-γ)·Φ⁻¹(1 - 1/N) + γ·Φ⁻¹(1 - 1/(N·e))` with γ = 0.5772156649 and **C = 0 when N ≤ 1**: `maxAttainableDsr = Φ( SRp·sqrt(n-1) / sqrt(1 + SRp²/2) − C )`. The denominator is the normal-moment form of the estimator's `denom`; the terminal evaluation still uses realized skew/kurtosis, so the assertion is an upper bound and refusing on it is conservative.

If the declared Sharpe falls below the requirement for the reserved window, the seal is refused. Running a two-year forward experiment that cannot detect its own hypothesized effect wastes the one asset preregistration exists to protect — the never-inspected forward window.
- **No gate threshold changed — stated defensively.** This is explicitly **not** QDR-7's rejected "relax the QDR-6 promotion gates so a near-miss becomes ACCEPTED". ### QDR-10: Product class (ALPHA | BETA) is declared irreversibly at seal, and BETA-class versions are promoted on volatility/drawdown/capture/cost criteria instead of the DSR-versus-zero alpha gate
Decision: every preregistration declares a **product class** — `ALPHA` or `BETA` — in its sealed config, and **that declaration is irreversible for that strategy/parameter version**. A version preregistered as ALPHA that fails QDR-6's gate may **never** be re-classified as BETA to obtain a friendlier criterion set, and a BETA version may never be re-classified as ALPHA to claim an edge it was never tested for; re-classification requires a **new version entering at `CANDIDATE` with a fresh forward window and fresh evidence**, and the prior version's terminal card stands unedited. `productClass` is part of `stableConfigHash(config)`, so changing it after seal breaks the `configHash` recomputation and fails QDR-9 condition (a) — the guardrail is enforced by machinery already shipped, not by reviewer diligence. **Absence of `productClass` resolves to `ALPHA`** (fail-closed to the strictest gate). ALPHA class is byte-identical to QDR-6/QDR-7/QDR-9 as written and keeps the terminal labels `ACCEPTED`/`REJECTED`. **BETA class replaces exactly one thing — the Deflated-Sharpe-versus-zero promotion gate — with four criteria that test the claims a risk-managed market-exposure product actually makes** (volatility control, drawdown control, no return destruction versus a sealed benchmark, cost honesty), keeps every hard safety gate byte-identical, terminates in the distinct labels **`ACCEPTED_BETA`/`REJECTED_BETA`**, and may make **no alpha claim anywhere**.
Options: (i) **seal the honest 14.72-year confirmatory lane** — at the research director's ex-ante annualized Sharpe **0.65** for the strongest measured mechanism (vol-targeted sector-capped inverse-volatility risk parity; the measured 1.13 was refused because ~+0.16 comes from a 2026-survivor sleeve and the 2017–2026 regime's own market Sharpe was ~0.90 against a ~0.50 long-run expectation), 80% power needs **742 five-session observations = 3,710 sessions = 14.72 years** (rejected: it is statistically correct and operationally indistinguishable from QDR-9's rejected "decade-long unfalsifiable wait" — the program would carry zero ACCEPTED strategies until 2041) / (ii) **seal a shorter, openly underpowered window** — 6.47 years buys ~50% power and 8.75 years ~61% at Sharpe 0.65 (rejected: a coin-flip test is not evidence, and QDR-9's power assertion exists precisely to refuse burning the one never-inspected forward window on a test that cannot detect its own hypothesized effect) / (iii) **invest in cross-market data breadth (TASI + NASDAQ + GCC, more mechanisms) to raise achievable Sharpe above the 1.11 an 80%-powered five-year ALPHA ACCEPTED requires** (rejected *as the answer to this problem*, not as work: it is a multi-quarter data-licensing and ingest program gated on QOQ-1/QOQ-2, it cannot produce a verdict on the mechanism already measured, and no honest long-only halal equity book in the **current** universe supports true Sharpe ≥ 1.11 — but it is **complementary, not mutually exclusive, and remains the only route to a genuine ALPHA `ACCEPTED` in this program**; QDR-10 must never be cited as a reason to stop pursuing it) / (iv) **a separate, irreversibly-declared BETA promotion criterion matched to the beta claim** (chosen: it lowers no threshold, leaves the alpha gate and every safety gate untouched, and collapses the required window by testing a claim that is statistically cheap to verify instead of one the product never made).

### QDR-11: A COMPARATIVE DIVERSIFICATION criterion set for universe-construction claims — measured against the incumbent rule at the same formation dates, entitling no return claim of any kind
Decision: a setup whose **entire hypothesis is that a universe-construction rule builds a better-diversified book than the incumbent rule** may seal with `productClass: 'DIVERSIFICATION'` and be adjudicated on **two comparative criteria** — **(D1) effective-bet ratio ≥ 1.10** and **(D2) realized book-volatility reduction ≥ 5%**, both measured against the **incumbent rule re-run at the same formation dates, on the same universe, at the same sleeve size** — with every hard safety gate byte-identical and **no return, Sharpe, edge, or outperformance claim permitted anywhere, ever, for that version**. Rationale: the measured diagnosis is that **the universe rule was the defect**. The halal NASDAQ sleeve holds **98 names at average pairwise correlation 0.326**, which by `effectiveBets(rho, n) = 1 / (rho + (1−rho)/n)` is **~3.0 independent bets**. Sixteen preregistered strategies then failed on concentration the *universe rule* built for them; no amount of further strategy search inside a three-bet sleeve can fix a three-bet sleeve. The decisive fact is that **the same intervention supports two claims with wildly different provability**, and this record exists to accept one and permanently refuse the other. The **return** claim: IR 0.111–0.263 against the honest comparator ⇒ **89 to 503 years** for 80% power — permanently unprovable, at any window, in any class, and no estimator rescues it because the effect is small, not badly measured. That is QDR-10's asymmetry one level down — **variance and covariation converge fast, means converge glacially** — and the correct response is the same one QDR-10 made: match the instrument to the claim, and say plainly what the claim is not.

The map **file's content hash** is part of `stableConfigHash`, so it cannot be quietly re-tuned between runs — a re-labeled sector is a re-run of the selection rule wearing a data update's clothes.
- **Observation unit: DAILY is permitted for D1/D2 specifically, and this is not unit-shopping.** For a **mean/Sharpe** statistic, required annualized Sharpe ≈ `(1.6449 + C) / √oosYears` — it depends on the window in **years**, not on how finely the window is cut, so re-cutting five-session blocks into daily ones buys **exactly zero** power for a return claim. That frequency-invariance was established in QDR-9 and **is unchanged; ALPHA and BETA keep their sealed non-overlapping observation units and may not re-cut them.** For a **variance-ratio** statistic the SE is `√(4/(n−1))` in **observations**, and daily returns are genuinely ~5 near-independent draws of the variance process where one five-session block is one — so finer sampling is **real information about the gated quantity**, roughly 5× more efficient. Permitting the daily unit here therefore buys nothing on the axis where shopping would pay, and this class makes no return claim at all, so there is nothing to shop for. **Daily is also the floor: intraday sampling is REFUSED for this criterion**, because bid-ask bounce and non-synchronous trading bias realized variance and would bias the two arms **unequally** — the decorrelated arm holds the less liquid names by construction.
- **The 100-observation floor is NOT reduced, and floor-shopping is closed by a calendar rule.** `INSUFFICIENT_SAMPLE` fires below 100 observations exactly as today, satisfied here in the daily unit (644 ≥ 100). To prevent a lane from clearing the floor merely by re-cutting a short window, the OOS window must **additionally span at least as many trading sessions as the 100-observation floor at the incumbent version's own sealed observation unit** — for a five-session incumbent that is **500 sessions**, and the candidate's 644 clears it. This rule invents no new number: it is the existing floor restated at the existing unit.
- **NO RETURN CLAIM IS PERMITTED — this is a contract violation, not a wording preference.** Not on the terminal card, not in `docs/STRATEGY_LAB.md`, not in `messages/en.json` or `messages/ar.json`, not in any UI surface. **Permitted claim vocabulary, exhaustively:** diversification, effective bets, pairwise correlation, book volatility, universe-construction rule, sector balance, Sharia compliance (التنويع · عدد الرهانات الفعّالة · الارتباط الزوجي · تقلب المحفظة · قاعدة اختيار الأسهم · التوازن القطاعي · التوافق مع الشريعة). **Banned, exhaustively as a starting list:** everything QDR-10 bans for BETA, plus higher return, better performance, higher Sharpe, improved returns, "1.13×", information ratio, and any inter-arm return comparison in either direction (عائد أعلى · أداء أفضل · نسبة شارب أعلى · تحسّن العائد). The card must print the treatment arm's `deflatedSharpe` under QDR-10's existing "reported, not a gate" annotation, extended with the literal line **"no return or Sharpe comparison between the two arms is reported; that difference needs 89–503 years of data for 80% power and is beyond measurement"** (Arabic: «لا تُقارَن العوائد أو نسبة شارب بين المحفظتين؛ فقياس ذلك الفارق يحتاج من ٨٩ إلى ٥٠٣ سنوات من البيانات وهو خارج حدود القياس»). Any copy change under this class is gated by **i18n-fintech-expert** review under the parent contract's rule; a violation blocks the change and shipped violating copy is a defect to be fixed, not debated.
- **The mirror obligation: the return GIVE-UP must be disclosed, and is likewise not a claim.** The candidate predicts a **~4.1pp CAGR give-up**. A record that forbids claiming a return gain while permitting silence about a return loss would be dishonest in exactly one direction. So the card **must** print both arms' realized CAGR and their difference, annotated verbatim **"the difference in return between the two arms is not statistically distinguishable from zero at this sample size and is neither claimed nor denied, in either direction"** (Arabic: «الفارق في العائد بين المحفظتين غير قابل للتمييز إحصائيًا عن الصفر عند هذا الحجم من البيانات، ولا يُدّعى ولا يُنفى في أي اتجاه»). Disclosure with that annotation is not a claim; omission would be a claim by silence.
- **A/B ISOLATION is a seal-time refusal: exactly one variable, against a named prior sealed version.** The two arms' configs must be identical except the universe-selection block. `comparatorVersionId` must name a **real prior sealed version** (here `halal-risk-parity-core@v1`: monthly month-end rebalance, inverse-volatility `1/sigma` on 252d, 20% per-name cap, 15-name breadth floor, `maxNames` 40, `seed` 42, 30% OOS — held **byte-identical**), never a strawman constructed for the occasion. `sealExperiment` **throws** if more than the universe block differs, or if `comparatorVersionId` resolves to no sealed manifest. A novel strategy therefore **cannot** enter as DIVERSIFICATION.
- **Plateau stability, restated in this claim's unit — QDR-6's existing profit-plateau guardrail, not a new criterion.** The sealed plateau is `{sectorCap 0.20 | 0.25 | 0.30} × {poolSize 60 | 80 | 100}` = 9 cells, **named at seal**. The **sealed cell** (`sectorCap 0.25`, `poolSize 80`) is the only cell that gates D1/D2; **all 9 cells must show a mean effective-bet ratio ≥ 1.00**, or the result is a knife-edge parameter artifact and the run fails with `betaCriterionFailures`-style code `PLATEAU_INSTABILITY` under `OOS_FAILURE`. All 9 cells are computed **inside the single terminal evaluation**, so QDR-9 condition (f) ("exactly one terminal evaluation exists for the version") holds unchanged; and because the sealed cell was named before any OOS contact, the other 8 can only **fail** the run, never rescue it — so no selection occurs and no trial-count inflation follows.
- **Every hard safety gate stays byte-identical and still applies.** The Sharia hard veto and `VERIFIED_COMPLIANT` requirement (`SHARIA_NON_COMPLIANT` / `SHARIA_UNVERIFIABLE`, fail-closed, execution-blocked when unscreened); the **Monte Carlo p95 max drawdown ≤ 30%** breaker; the **5% risk-of-ruin** limit; the Sharpe > 3.00 implausibility ceiling; PIT and data-quality integrity; reproducibility (seed, git SHA, run artifact, deterministic replay); the **100-observation floor**; the ≥20–30% contiguous OOS holdout; and **all of QDR-9's confirmatory machinery** — the six structural conditions, the out-of-band `sealedAt` rule, the fail-closed EXPLORATORY default, and the throw-on-incomplete gate block. Nothing in this record makes any of them easier.
- **A diversification improvement is NOT a licence to pass a risk gate — and the flagship candidate is expected to be REJECTED on drawdown.** `halal-decorrelated-risk-parity-core@v1` predicts **MC p95 max drawdown 41.0%** against the **30%** breaker. If it seals and realizes as predicted, its terminal label is **`REJECTED_DIVERSIFICATION`**, and that is the **correct** outcome. A hard safety gate failure is terminal for the admission regardless of how strong D1 and D2 come back: **passing D1 and D2 while failing the breaker never yields an ACCEPT.** The measured D1/D2 figures are still recorded on the rejected card as ledger evidence that a **future** version — one that also fixes drawdown, on its own fresh seal and fresh window — may cite. This record creates no exception, no waiver, and no partial-accept state.
- **A predicted breaker failure does not refuse the seal, but it must be disclosed at the seal.** The acceptance set is not *provably* empty (the drawdown prediction could be wrong), and the structural finding is separable and cheap — 2.56 years to settle, against 89–503 for the return question — so QDR-9's feasibility assertion does not fire. But `hypothesizedMonteCarloP95Drawdown` is **required** in the gate block, and a declared value above the breaker forces the literal manifest and card line **"this lane is predicted to fail the drawdown breaker and is therefore predicted to terminate REJECTED; it is sealed to adjudicate the structural claim only and is not a candidate for admission"** (Arabic: «يُتوقَّع أن تُخفق هذه التجربة في حدّ الانخفاض الأقصى وأن تنتهي بالرفض؛ خُتمت للفصل في الادعاء البنيوي فقط وليست مرشّحة للقبول»). It may not be described as a candidate for admission anywhere while that line is live.
- **Seal-time power assertion sits on D2, the binding criterion.** The reserved window must satisfy the daily-observation requirement above at the declared `hypothesizedVolReduction` (≥80% power; **n ≥ 407** at 11.6%), **and** the D1 hypothesis must be declared as `hypothesizedEffectiveBetsRatio` with the walk-forward evidence that supports it (here 1.28× over 8/8 periods, 2017–2024). A seal that declares an effect its window cannot detect is **refused**, exactly as under QDR-9. The gate block gains `productClass`, `comparatorUniverseRule`, `comparatorVersionId`, `sectorMapHash`, `formationCadenceDays`, `correlationLookbackDays`, `minEffectiveBetsRatio`, `minVolatilityReduction`, `hypothesizedEffectiveBetsRatio`, `hypothesizedVolReduction`, `hypothesizedMonteCarloP95Drawdown`, `bootstrapBlockLength`, `plateauCells`; **present-but-incomplete throws at seal**, absent-entirely seals as EXPLORATORY `ALPHA` — the fail-closed default is untouched.
- **Anti-gate-shopping — three independent locks, two of them already shipped.** (1) **Hash-enforced irreversibility**: `productClass` is inside `stableConfigHash`, so mutating it after seal breaks `configHash` recomputation and fails QDR-9 condition (a). There is no re-class path, no appeal, no "re-run under the other class" — the only route is a **new version at `CANDIDATE`** with a fresh window whose evidence boundary is strictly after its own new seal, so recycled data cannot fund a second attempt. (2) **There is nothing to shop for**: a setup that would fail ALPHA's DSR gate gains **no return claim whatsoever** by declaring DIVERSIFICATION, and gains **no capital, no allocation, and no tournament entry** — it permanently forfeits the ability to report a return result for that version in exchange for permission to use a selection rule. Gate-shopping is only attractive when the cheaper gate pays out something the expensive one would have; this one pays out nothing on that axis. (3) **Structural admissibility**: the class requires a named prior sealed comparator version and exactly one changed variable, so a setup with no incumbent — or with a new signal, a new sizing rule, or a new rebalance cadence smuggled alongside — cannot declare it, and `sealExperiment` throws rather than warns.
- **Implementation is one roadmap row, `G9` (§9b), owner quant-strategist — and it is small, because the machinery exists.** Add `'DIVERSIFICATION'` to `ProductClass` in `src/quant/backtest/gatePower.ts` (leaving `productClassFromConfig`'s absent-⇒-`ALPHA` fallback byte-identical), add a `DiversificationGateSpec` mirroring `BetaGateSpec` with `assertDiversificationGateSpec` + `assessDiversificationGateFeasibility`, add `src/quant/backtest/diversificationCriteria.ts` mirroring `betaCriteria.ts` with `DIVERSIFICATION_CRITERION_CODES = ['EFFECTIVE_BETS_RATIO', 'BOOK_VOLATILITY_REDUCTION', 'PLATEAU_INSTABILITY']`, widen `TerminalValidationStatus`, and wire the paired bootstrap into the existing block-bootstrap module. **Reused, not rebuilt** (lazy-dev): `pearson` and `effectiveBets` from `decorrelatedSleeve.ts`, `selectDollarVolumeSleeve` / `selectCorrelationBalancedSleeve` from `sleeveSelector.ts`, `portfolioEngine.ts` for both arms, the existing block bootstrap, and `contiguousHalves` where a half-window read is reported. **No new Prisma model, no migration, no new dependency, no new service, no cron, no queue.** **Zero-key mode is a first-class citizen and is unaffected**: every D1/D2 quantity is computed from persisted bars through the existing keyless captured-real-data fixtures tier, so `npx vitest run quant-diversification` must pass with **no API keys set**.
Revisit when: the **1.10** effective-bet-ratio floor or the **5%** volatility-reduction floor is proposed to move, a **third** gated criterion is proposed, a **return claim of any kind** is proposed for this class, or a **re-classification path** into or out of DIVERSIFICATION is proposed — **each reopens QDR-11 in full and requires a fresh record, never an edit here** (the same rule QDR-10 applied to itself, and which produced this record); or a DIVERSIFICATION lane is proposed whose incumbent has **no prior sealed version**, at which point the comparator definition needs its own record before any such seal; or sampling finer than daily is proposed, which requires a published measurement of microstructure variance bias **for both arms separately** before it may be considered; or an `ACCEPTED_DIVERSIFICATION` rule is adopted by a later version that then fails its own ALPHA/BETA gate in a way traceable to the rule (the rule's admission is withdrawn for **future** versions on a new record; every existing card stands unedited); or the incumbent dollar-volume rule is replaced program-wide, at which point every prior DIVERSIFICATION card's comparator must be re-labeled as historical rather than current.

### QDR-12: The comparator definition for an incumbent that predates the manifest protocol — a CLOSED, historically-fixed anchor set, admissible for A/B identity only and never as evidence
Decision: a DIVERSIFICATION lane (QDR-11) whose `comparatorVersionId` names a version that was **preregistered by commit before the manifest protocol existed** may resolve that comparator against a **closed registry of HISTORICAL ANCHORS** held in code (`src/quant/backtest/historicalAnchors.ts`), instead of against a sealed manifest file. An anchor is admissible **only** to establish (i) that the comparator rule is a **real prior committed mechanism** rather than a strawman constructed for the occasion, and (ii) the **A/B-isolation config diff** — exactly one variable. An anchor is **never** evidence: it contributes no result, no card, no metric, no allocation, and may not be cited in support of any claim. This is the fresh record QDR-11's Revisit-when demanded ("a DIVERSIFICATION lane is proposed whose incumbent has **no prior sealed version**, at which point the comparator definition needs its own record before any such seal"); **QDR-11's text is not edited and none of its criteria are changed, eased, or extended.**
Options: (i) **refuse the class until the incumbent is re-sealed on a fresh forward window** (rejected: it costs a forward window to re-establish a commitment that demonstrably already exists, and the re-seal would be measurably *weaker* evidence than the artifact it replaces — see Rationale. It would also freeze the class for years over a one-day gap in tooling history) / (ii) **retroactively author a SEALED manifest for the incumbent** (rejected, and this is the option that must never be taken: a manifest written today would carry an `evidenceBoundary` after its own results and a `sealedAt` after its own terminal card. That is a fabricated preregistration — precisely the artifact the entire protocol exists to make impossible — and it would be indistinguishable, on inspection, from an honest one. The whole value of a seal is that it cannot be produced after the fact; producing one after the fact destroys that value for **every** manifest in the inventory, not just this one) / (iii) **drop the sealed-comparator requirement for DIVERSIFICATION** (rejected: it is the single clause standing between this class and a comparator chosen to flatter the treatment — the failure that produced a **29.6%** figure where the honest one was **11.6%**, a 2.6× overstatement caused entirely by comparator choice with no error in the mechanism at all) / (iv) **a closed historical-anchor registry, admissible for identity and isolation only** (chosen: it recognizes a commitment that genuinely predates the tooling, while making the set impossible to grow and the anchors impossible to cite).
Rationale: the incumbent `halal-risk-parity-core@v1` was frozen by commit **`6e5a095` on 2026-07-20**, whose message is literally *"feat: preregister halal-risk-parity-core v1 (inverse-vol risk parity)"*. `src/quant/backtest/experimentProtocol.ts` — the manifest protocol itself — first appeared at **`cf41f13` on 2026-07-21**, and the first manifest file at **`310b366` on 2026-07-22**. The missing manifest is therefore a **protocol-migration artifact one day wide**, not a missing commitment. The decisive observation is that the historical artifact is **stronger** provenance than a fresh seal would be, on the exact axis the requirement cares about: the git SHA predates the run, the mechanism has since been adjudicated to a **published terminal card** (`REJECTED`; run `214b6a94-9437-4a18-bf9d-efe42652d197`; `docs/STRATEGY_LAB.md`), and neither could have been arranged with the present comparison in view — whereas a manifest sealed **today**, for the declared purpose of anchoring this comparison, would be constructed for the occasion in the ordinary meaning of that phrase. Grandfathering here is not a relaxation; refusing it in favour of a fresh seal would substitute weaker evidence for stronger and call the substitution rigour.
Consequences:
- **The set is CLOSED by a historical fact, not by discipline — this is the load-bearing fence.** An anchor is admissible only if its preregistration commit is an ancestor of, and dated strictly before, **`cf41f13` (2026-07-21)**, the commit that introduced the manifest protocol. That date cannot move, so the admissible set **can never grow**: every version preregistered from 2026-07-21 onward had the protocol available and has no excuse. A proposal to add an anchor whose commit postdates the epoch is not a judgement call to be weighed — it is refused, and `historicalAnchors.test.ts` pins the closure.
  - **CORRECTION OF RECORD — 2026-08-08, raised at quant-research-director ratification.** This bullet originally read "*it is refused by arithmetic*", and that was an **overclaim** at the time it was written. `assertAnchorAdmissible` compared only the anchor's **self-declared** `preregisteredAt` string against the epoch and checked that `preregistrationSha` was non-empty; it never asked git what that SHA's commit date actually was. An entry carrying a fabricated date before the epoch and any non-empty SHA string would have passed. Enforcement was therefore **code review plus a length-pinned test** — process, not arithmetic — and the distinction matters precisely because unforgeable closure is the load-bearing claim of this record. **Closed 2026-08-08:** `historicalAnchors.test.ts` now shells out to `git show -s --format=%ad` for every anchor's **real** commit date, asserts it equals the declared date, asserts it precedes the epoch, and asserts `MANIFEST_PROTOCOL_EPOCH` equals the date `src/quant/backtest/experimentProtocol.ts` was actually introduced. The registry cannot forge any of those. The claim is now true; it is recorded here as having been false when made, rather than quietly repaired, so the gap between a record's confidence and its evidence stays auditable.
- **The registry lives in CODE, never as a droppable file.** A JSON file in `docs/quant-experiments/` could be added by anyone with write access and would look, to the resolver, exactly like a real manifest. A frozen `const` in `src/quant/backtest/historicalAnchors.ts` is reviewable, diffable, and cannot be introduced without a code review that shows the whole record.
- **The resolution path STRIPS the anchor's audit metadata, so identity-only is structural, not merely intended.** `terminalRunId`, `terminalStatus` and `ledgerRow` exist so a reader can audit the reconstruction against the SHA it claims; they are exactly the fields a future card renderer could join against real metrics. The resolver therefore returns only `{versionId, sealed, config}` — the audit fields never leave the registry — and a test pins that shape so it cannot widen unnoticed. *(Raised at quant-research-director ratification 2026-08-08 as an attractive nuisance rather than an active leak; the stripping already held, and is now asserted.)*
- **An anchor is IDENTITY and ISOLATION, never EVIDENCE — stated exhaustively.** Admissible uses: resolving `comparatorVersionId` to a real prior mechanism; supplying the config the A/B-isolation diff runs against. Inadmissible uses, as a starting list: any metric, CAGR, Sharpe, drawdown or effective-bet figure; any terminal card; any league or tournament row; any allocation; any citation in `docs/STRATEGY_LAB.md` beyond the row it already has; any claim that the anchored version was "sealed" or "preregistered under the manifest protocol", which it was not. The anchor's own `terminalStatus` is recorded as `REJECTED` **solely** so a reader cannot mistake it for an admitted strategy.
- **The comparator ARM is still a fresh run under the identical PIT schedule, exactly as QDR-11 requires.** The anchor supplies the RULE's identity and config; it supplies no results. QDR-11's clause — "the comparator is a fresh run of the incumbent rule under the identical PIT schedule, and the incumbent's terminal card is neither revisited, re-scored, nor re-run" — is unchanged and unaffected. Nothing in this record lets a prior card become a comparator.
- **The A/B-isolation diff gains real teeth, not less.** The anchor's config is a **reconstruction from the committed code at its preregistration SHA**, hashed like any other, and the QDR-11 diff runs against it unchanged: `universe` is the one permitted variable, while `signal`, `portfolio`, `execution`, `plateau` and `seed` must match byte-for-byte. A treatment that smuggles a second variable is refused identically to one facing a sealed manifest.
- **The reconstruction must be auditable against the SHA it claims.** Each anchor records `preregistrationSha`, `preregisteredAt`, `terminalRunId` and its ledger row, so any reader can check the reconstruction against the code at that commit. A reconstruction that cannot be checked that way is not admissible, and an anchor whose fields do not resolve is a defect to be fixed, not a discrepancy to be tolerated.
- **Every hard gate is untouched.** No threshold moves. The Sharia veto, the 30% MC p95 drawdown breaker, the 5% risk-of-ruin limit, the Sharpe > 3.00 ceiling, PIT and data-quality integrity, reproducibility, the 100-observation floor, the OOS holdout, QDR-9's confirmatory machinery, and every QDR-11 criterion apply to the DIVERSIFICATION lane exactly as before. This record changes **what may anchor a comparison**, and nothing else.
- **This record needs quant-research-director ratification before a seal relies on it.** It was drafted by the implementer during G9, which is the wrong owner for a design record under the parent contract's routing (design → architect/director only). It is written, implemented and tested so the decision is concrete rather than hypothetical, but a seal citing it should carry the director's sign-off.
Revisit when: an anchor is proposed whose preregistration commit does **not** predate `cf41f13` (refused by the epoch rule — this reopens QDR-12 in full and requires a fresh record, never an edit here); or an anchored version is proposed as **evidence** for any claim in any direction (likewise refused, and the proposal itself indicates the identity/evidence boundary is not holding in practice); or a reconstruction is found to disagree with the code at its declared SHA (the anchor is withdrawn immediately and every seal that relied on it is re-examined); or the manifest protocol is replaced, at which point the epoch and this record's rationale must both be restated against the new protocol's own introduction date.

### QDR-13: A declared `runConfig` echo and an explicit `gateConfig` parameter make the sealed BETA/DIVERSIFICATION gate block reachable — by both `assertFrozenCliConfig` and `runLab` — instead of silently resolving to ALPHA

Decision: **MEASURED, not hypothesised — two distinct wiring defects, not one, both fixed here.** (1) At run time, every classification read in `src/quant/backtest/runLab.ts` — `productClassFromConfig`/`gateSpecFromConfig` at the `sealedSpec`, `declaredCells`, and top-level `productClass` sites, plus `betaGateDeclaration` — is called on `effectiveParams` (`params ?? setup.defaultParams`, e.g. `HALAL_SPUS_VOL_MANAGED_BETA_V1`), never on the sealed manifest. `effectiveParams` has no `validation` key and structurally cannot (`HalalSpusVolManagedBetaParamsSchema` admits only `version`/`volatilityLookbackSessions`/`targetAnnualVolatility`/`validationTrials`), so `productClass` resolves `ALPHA` on every run of either lane regardless of what the sealed manifest declares — reproduced directly against both frozen params objects. (2) Independently, `scripts/backtest.ts`'s `assertFrozenCliConfig` requires `manifest.configHash === stableConfigHash(protocolConfigForOptions(options))` — the **entire** sealed config byte-equal to an 11-field CLI-args echo (`setup`/`period`/`from`/`to`/`universe`/`symbols`/`confirmFull`/`candidatesPath`/`seed`/`oosFraction`/`engine`/`feed`/`source`) — so any manifest whose sealed config also carries a `validation` gate block (or `plateau`, `hypothesis`, anything else) can never satisfy it and can never reach `FULL_CLAIMED`. Between the two clauses in tension — "the gate block lives in the sealed config, and that hash is the anti-gate-shopping guardrail" (QDR-10) versus "the sealed config hash-equals the CLI-args shape" (`assertFrozenCliConfig`) — **the second gives way, not the first.** `assertFrozenCliConfig`'s formula was never itself a QDR decision; it is an unrecorded implementation assumption, written when every manifest that existed WAS CLI-shaped (still true of `halal-residual-fast-momentum-core-v1.json` today), and it is not the mechanism QDR-9/10/11 name as the guardrail — `configHash` is. `assertFrozenCliConfig` narrows its comparison from "the whole sealed config" to a **declared `runConfig` sub-object** — a sibling of `validation` inside the SAME `manifest.config`, holding exactly the JSON `protocolConfigForOptions` already builds from CLI args — so one sealed, hashed object can carry both an operational echo and a gate block. Separately, and fixing failure (1), `RunLabOptions` gains an explicit `gateConfig` field carrying `manifest.config.validation`, threaded into `runLab` by the CLI wrapper immediately after `assertFrozenCliConfig` proves the run matches the sealed manifest — so BETA and DIVERSIFICATION are finally read from the artifact QDR-9/10/11 actually mean by "the sealed config," not from a same-named stand-in that was never connected to it.

Options: (i) **put the gate block in the strategy's own `defaultParams`** so `effectiveParams` naturally carries `validation` (rejected: `setup.defaultParams` is a TypeScript source constant that nothing ever hashes as sealed — `HALAL_SPUS_MANIFEST_CONFIG_HASH` cross-checks only the four zod-schema fields, never a `validation` sub-object — so a later commit could edit `productClass`/`volCeiling` with zero detectable hash mismatch, which is exactly the failure QDR-10 built the hash to prevent; it also duplicates the gate block in two unsynchronized places, and would let a manifest-less/exploratory run — a real, common path, `if (!manifestPath) return runLab(options)` — execute as BETA/DIVERSIFICATION purely because the strategy source says so, silently breaking "absent manifest ⇒ EXPLORATORY ALPHA") / (ii) **make `runLab` read the manifest's entire rich config wholesale, in place of `effectiveParams`** (rejected: the manifest's rich config — `evidenceBoundary`/`universe`/`signal`/`portfolio`/`execution`/`validation`/`plateau`/`hypothesis` — and the strategy's zod-validated tuning params are different shapes for different jobs; feeding one wholesale into the other either throws at the strategy's own schema parse or demands a bespoke per-setup reshaping adapter, reopening the identical "two objects, one name" confusion one level down. It also does not touch `assertFrozenCliConfig` on its own — a manifest that IS `effectiveParams` wholesale still must satisfy the unchanged CLI-shape hash check to ever reach `FULL_CLAIMED` — and it entangles every manifest-less diagnostic run with a manifest that, for that run, does not exist) / (iii) **loosen or remove `assertFrozenCliConfig`'s equality** (e.g. check only `setupId`) (rejected: this deletes the only proof that a terminal FULL run's actual dates/seed/engine/feed match what the preregistration declared, letting a runner claim FULL against a manifest while quietly running different inputs than what was sealed — the same undetected-drift failure QDR-9's hash-anchoring exists to close, moved to the operational axis instead of the classification axis; a deletion of a guardrail, not a fix) / (iv) **derive a CLI-shaped echo automatically from the rich config's existing fields** (map `universe.tradable`/`seed`/etc. into the 11 CLI fields, no new authored field) (rejected: the rich schema varies per lane — the BETA lane's `universe.tradable: ['SPUS']` versus the DIVERSIFICATION lane's `universe.rule`/`maxNames`/`sectorCap` versus the CLI's plain `universe?: 'halal'|'wide'|'custom'` string — and neither rich schema has a canonical source for `period`/`engine`/`feed`/`candidatesPath`; this demands bespoke, per-manifest-shape mapping code that can silently drift from intent, where an explicit author-filled field costs nothing and needs no mapping code at all) / (v) **a declared `runConfig` sub-object narrows `assertFrozenCliConfig`, and a threaded `gateConfig` parameter gives `runLab` the sealed `validation` block directly** (chosen: it changes one comparison and adds one parameter, moves no threshold, requires zero migration for any manifest with no gate block, and is the only option that repairs both failures — the runtime misread and the CLI-shape refusal — without inventing a new hash, a new service, or a new file format).

Rationale: the two "config" objects in this system share a name and a hash function but never shared a wire. `src/quant/backtest/experimentProtocol.ts`'s `assertGateFeasibleAtSeal`, `assertStatusMatchesSealedClass`, and `assertDiversificationComparator` already call `productClassFromConfig`/`gateSpecFromConfig` on `manifest.config` — the true sealed artifact — and have done so correctly since G8/G9 shipped; QDR-9's seal-time feasibility and power assertions, and QDR-11's A/B-isolation refusal, all work exactly as designed at seal time. The break is entirely downstream, in the two places that consume a manifest AFTER it is sealed. `runLab.ts` never receives `manifest.config` at all — only `RunLabOptions`, parsed from CLI args — and derives `effectiveParams` from the strategy's hardcoded `defaultParams`, an object never meant to carry a gate block and, for both lanes in question, structurally unable to. And `assertFrozenCliConfig`, written when the only manifests in existence were CLI-drafted, demands the entire sealed config match the CLI args — vacuously true for a CLI-shaped manifest, structurally impossible the moment a manifest also carries `validation`/`plateau`/`hypothesis`. Both defects fail closed to ALPHA, which is why nothing was ever wrongly ACCEPTED — but it also means BETA's four criteria and DIVERSIFICATION's D1/D2/plateau checks, specified at length in QDR-10 and QDR-11, have never once executed for their intended class.

### QDR-14: A declared, disclosure-bound survivorship-coverage waiver makes a terminal DIVERSIFICATION run reachable on free data — `suspended` coverage may never be proven from any free source, so the fence opens by honest disclosure, never by silent relaxation

Decision: `lifecycleCoverage.suspended: false` **may** permit a terminal card, but only through a new, structurally declared **survivorship-coverage waiver** — never by loosening `assertPointInTimeMembershipCoverage`'s existing check — and only for `productClass: 'DIVERSIFICATION'` (`src/quant/backtest/gatePower.ts`'s existing `ProductClass` union, reused unchanged). ALPHA and BETA runs are **untouched**: they still refuse unconditionally on `suspended: false`, exactly as today, because they make return/risk claims a survivorship gap can corrupt undetectably. `lifecycleCoverage.delisted: false` is **never** waived, for any class — delisted coverage is achievable (161 of 217 candidate symbols carry complete Form-25 evidence per `pitDelistingLifecycle.ts`'s own coverage finding) and stays the unwaivable half of the guard. The 55 symbols whose delisted coverage fails closed to `UNKNOWN` are **excluded from the eligible universe** for any DIVERSIFICATION sleeve pool — carried nowhere, disclosed nowhere as a gap, simply not candidates — never admitted with an asterisk. The OOS fraction moves from **0.30 to 0.50**: 0.30 is arithmetically infeasible (644 required observations against 1,540 sessions in the corrected, membership-PIT-bounded window 2020-05-31..2026-07-17 needs ≥41.8%), and 0.50 is the smallest round value clearing that floor with a multi-month margin. An OpenFIGI ISIN→ticker crosswalk is **admissible PIT evidence for identity resolution only** — closing the ten-filing, 1,004-day N-PORT membership hole — on the identity/evidence boundary QDR-12 already drew for historical anchors, and only when the resolved ticker's company name is cross-checked against the filing's own disclosed `<name>` element (the defense against ticker reuse). Every card sealed under the waiver must print a mandatory bilingual survivorship-bias disclosure naming the residual risk and its direction, in the QDR-10/QDR-11 mandatory-disclosure grammar.

Options: (i) **refuse permanently — the fence never lifts on free data** (rejected as the answer, though it is the honest default absent this record: DIVERSIFICATION makes no return claim and terminates in `UNIVERSE_RULE_ADMISSION_ONLY` — no capital, no allocation, no tournament entry — so a permanent refusal here is refusing to adjudicate the one claim class in the whole program that is statistically cheap enough to settle and structurally incapable of moving money on a wrong verdict; the honest limitation belongs on the card, not as a reason to never print one) / (ii) **buy the data — a commercial market-data or compliance vendor's exchange-halt/trading-suspension feed** (rejected against the owner's own test: "prefer free-of-charge; a low cost is acceptable only if it buys measurable performance." No such vendor is free or low-volume-free the way OpenFIGI is; the cheapest tier is a recurring subscription, not a one-time cost, and it would buy **zero** measurable performance — D1/D2 have no threshold that moves, no card outcome that flips, and no capital that starts flowing based on suspension coverage; it would only delete one disclosure sentence for a residual risk this record already bounds by disclosure. Money spent to remove a caveat that costs nothing to state honestly fails the owner's test on its own terms) / (iii) **quietly treat `suspended: false` as compliant by default (fail-open) for this one lane** (rejected outright: this is the exact failure class the entire QDR-9–13 corpus exists to prevent — "never fail-open" is stated for the Sharia veto and assumed everywhere else; a silent fail-open on a coverage guard is indistinguishable, on inspection, from a bug, and this record's whole purpose is to make the exception visible, hashed, and printed, not invisible) / (iv) **build a free backfill from SEC's published Trading-Suspensions press-release page** (`sec.gov/litigation/suspensions`, already named as out-of-scope in `pitDelistingLifecycle.ts`'s own coverage-finding comment) (rejected **for now**, not forever: it is unstructured HTML, not a structured EDGAR filing type, so it is genuinely new parsing work comparable in scope to the Form-25 backfill already shipped — and worse, that page covers only SEC-ordered Section 12(k) suspensions (fraud / inadequate-information cases), a narrow category that does **not** include ordinary NASDAQ-initiated trading halts, which are the more common suspension type for an operating company. Building it would not even close the gap — it would convert "no source" into "one narrow, still-incomplete source," which still needs a waiver-boundary decision exactly like this one. Lazy-dev rung: do not build an ingest pipeline that doesn't solve the stated problem; disclose instead, and revisit if the source's scope is later shown to be closer to complete than currently understood) / (v) **a declared, hash-anchored, DIVERSIFICATION-only coverage waiver with a mandatory bilingual disclosure** (chosen: it lowers no ALPHA/BETA gate, invents no new pass/fail threshold, and matches the one claim class in the program where the consequence of an undetected coverage gap is bounded by an existing architectural fact — `UNIVERSE_RULE_ADMISSION_ONLY` already means an ACCEPT moves no capital and enters no tournament).

Rationale: `assertPointInTimeMembershipCoverage`'s snapshot-level check treats `delisted` and `suspended` symmetrically — both `false` throw `LIFECYCLE_COVERAGE_MISSING` — because the guard was written before any free source for either existed. That symmetry is no longer honest: `delisted` coverage is now **measured and partial** (161/217 complete via Form 25), while `suspended` coverage is **permanently zero** — no SEC form exists for a trading suspension that does not end in delisting, stated in `pitDelistingLifecycle.ts`'s own module comment. Treating a permanently-unobtainable fact identically to a partially-obtained one means the guard can never distinguish "we haven't backfilled this yet" from "this cannot exist," and a program that only ever adds free sources would wait forever for the second kind to resolve. **The residual risk has a direction, and it is adverse, not neutral.** A trading suspension freezes a name's last price; in daily-return terms a frozen price contributes zero variance and zero covariance with every other holding for the duration of the halt — which *understates* that name's measured volatility and *understates* its correlation with the rest of its basket. Because `selectCorrelationBalancedSleeve` (QDR-11's treatment arm) by construction holds the less liquid, more suspension-prone names, an undetected suspension is more likely to land in the treatment basket than the comparator, and would flatter **exactly** the arm this claim is trying to validate on **both** D1 and D2 simultaneously. This is not a symmetric, self-cancelling risk — stating it honestly, with its direction, is materially more informative than silence, and is the only posture available given zero free evidence exists to correct for it. The consequence of an undetected occurrence is bounded by architecture already in force: DIVERSIFICATION's `UNIVERSE_RULE_ADMISSION_ONLY` means even a false-positive `ACCEPTED_DIVERSIFICATION` moves no paper capital and enters no tournament — it only permits a **future** version to adopt the rule, and that version must still clear its own independent ALPHA or BETA gate on its own fresh evidence. A wrong verdict here is recoverable in a way a wrong verdict on a capital-allocating class is not; that asymmetry is what makes disclosure — rather than proof — an adequate instrument for this class alone.

Consequences:
- **(1) The waiver mechanism, concretely.** `PointInTimeUniverseSnapshot` gains one new optional field: `survivorshipWaiver: Readonly<{ suspendedCoverageUnavailable: true; reason: string }> | null`. `PointInTimeMembershipRequest` (and therefore `TerminalPointInTimeMembershipRequest`) gains `productClass: ProductClass` (the existing `gatePower.ts` union — no parallel enum invented). Inside `assertPointInTimeMembershipCoverage`, the existing single check `if (!snapshot.lifecycleCoverage.delisted || !snapshot.lifecycleCoverage.suspended) fail('LIFECYCLE_COVERAGE_MISSING', ...)` splits into two: `delisted: false` **always** fails, for every `productClass`, no exception — byte-identical to today on that half. `suspended: false` fails **unless** `request.productClass === 'DIVERSIFICATION'` **and** `snapshot.survivorshipWaiver !== null` — both conditions required, neither alone sufficient. For ALPHA, BETA, or any snapshot with no declared waiver, `suspended: false` fails exactly as it does today; this record changes behavior for **zero** existing call sites until a caller explicitly opts in on both axes.
- **(2) Per-record `LIFECYCLE_UNKNOWN` is untouched — the 55 symbols are excluded, not carried.** This record does not touch the per-record check at `pointInTimeMembership.ts:230-232`; a symbol resolving `lifecycle === 'UNKNOWN'` still fails `LIFECYCLE_UNKNOWN` unconditionally. The fix is upstream: the DIVERSIFICATION sleeve pool's `requiredSymbols`/candidate universe is restricted, before the guard is ever called, to the 161 symbols with complete Form-25 coverage. A DIVERSIFICATION run is therefore evaluated on a **coverage-complete subset** of the halal NASDAQ universe, never on the full 217 (or 216 — the source figures, 161 complete + 55 UNKNOWN, are quoted as measured and not force-reconciled here), and the card must print the pool size actually used (`lifecycleEligibleUniverseSize`) alongside the exclusion count, so no reader mistakes the tested pool for the full universe. `poolSize: 80` (the sealed DRAFT's declared value) fits inside 161 with room to spare, so this restriction does not by itself threaten feasibility.
- **(3) `delisted` coverage has to actually be wired before any of this matters.** `spusNport.ts:519` hard-codes `lifecycleCoverage: { delisted: false, suspended: false }` today — the `pitDelistingLifecycle.ts` Form-25 module exists but is not yet consumed by snapshot construction, so **every** DIVERSIFICATION run currently fails on the `delisted` half alone, before `suspended` or this waiver is ever reached. Wiring real per-symbol Form-25 evidence into the snapshot (so `lifecycleCoverage.delisted` and each record's `lifecycle` resolve from measured evidence, not a hard-coded constant) is a prerequisite of this record's reachability, not a separate concern — it is folded into the same roadmap row (G11, below) because a waiver on an unreachable check is theater.
- **(4) The OOS fraction: 0.50, named plainly, and why raising it is not gate-shopping.** 0.30 of the corrected 1,540-session window (2020-05-31..2026-07-17 — SPUS launched Dec 2019, so no formation date may precede N-PORT membership evidence) yields 462 daily observations against a required 644 — **provably infeasible**, the same failure class QDR-9's seal-time feasibility assertion exists to catch before, not after, a forward window opens. The floor is 41.8%; 0.50 is chosen over the bare floor for margin (770 observations, a multi-month buffer against exact-calendar edge cases in session counting) and because it is the smallest **round** value clearing the floor, not a value reverse-fit to any observed result. **This is not gate-shopping** on two independent grounds: first, no threshold this record could relax is being touched — D1's 1.10 and D2's 5% floor, DECIDED and out of scope for relitigation, are byte-identical; only the sample-split parameter moves, and a larger OOS fraction makes the terminal D1/D2 test *more* reliable (more observations, tighter confidence bounds), which is the conservative direction, never the permissive one. Second, `halal-decorrelated-risk-parity-core-v1.json` is `state: DRAFT`, `configHash: null`, `diagnosticRuns: 0` — no result has ever been seen at any `oosFraction`, so there is nothing this number could have been selected to flatter; it is derived from calendar arithmetic alone. The genuine cost — a smaller in-sample window (770 sessions, ~3.05 years, versus 1,078 at 0.30) — buys back nothing for this claim class, because D1/D2's sleeve-formation rule and the plateau's 9 cells are all fixed at seal, not fit against in-sample performance; the in-sample slice's only job here is supplying the trailing 252-session lookback the first rolling formation needs, and 770 sessions is comfortably more than that. **The manifest's `runConfig.from` (currently `2016-01-04`) and `runConfig.oosFraction` (currently `0.30`) both need correction before any seal** — this record does not edit the manifest (out of scope by the dispatch's own scope fence); the correction is the strategist's ordinary seal-time authoring step, informed by this record.
- **(5) The OpenFIGI crosswalk — admissible for identity, never for a time-varying fact, and the ticker-reuse defense.** An ISIN is a static identifier assigned once to a security; resolving `ISIN → ticker` through OpenFIGI answers "what symbol denotes this security," not "was this security held by SPUS on this report date" — the latter is already answered, for all 15 filings, by the N-PORT filing itself (which discloses the ISIN and the issuer's legal `<name>` even where it omits `<ticker>`, confirmed directly in the ten unparseable fixtures). The crosswalk therefore closes a **labeling** gap, not an **evidentiary** one, on exactly the identity/isolation boundary QDR-12 drew for historical anchors: admissible to resolve what a thing is, never admissible as a substitute for what happened. **What could break this distinction: ticker reuse.** OpenFIGI's mapping reflects the ticker **currently** assigned to an ISIN; if the underlying company was later delisted and an unrelated issuer was assigned the same ticker afterward, a live query today would return the *wrong*, recycled symbol for a 2020–2023 holding. The mitigant is required, not optional: a resolved ticker is accepted only if the company **name** OpenFIGI returns for that ISIN matches (case/punctuation-normalized) the issuer `<name>` already disclosed in the filing itself — an independent cross-check the crosswalk cannot silently fail. **Zero-key mode**: resolution happens once, at authoring time, and the result is captured and hash-pinned exactly as `SPUS_NPORT_FILINGS` already is — no live OpenFIGI call happens inside a test run or a sealed backtest, preserving the mock-first invariant through this record.

Because `productClass` and the rest of `validation` are already inside `stableConfigHash` (QDR-10, shipped), this declaration is irreversible for the version by the same machinery, not by diligence.

The two prior attacks on this engine changed SIZING (`halal-momentum-markowitz-core`, `halal-momentum-risk-parity-core`, both REJECTED, 52.95%/60.51%/0.746 and 51.17%/60.18%/0.753) and the third changed EXITS (`halal-stopped-fast-momentum-core`, DRAFT, died on a measurably inert parameter). Selection itself has never been improved beyond a raw price rank. A price signal cannot separate a run driven by business acceleration from one driven by re-rating or crowding; revenue growth is the only axis in the database that is never a function of price and directly measures the former. That is the causal mechanism, and it is aimed at the comparator's own diagnosed failure — a 68.40% MC p95 attributed to a fast-turning momentum cluster, and a plateau that collapses at 42d because the price signal turns noisy.

Consequences:
- **Measured coverage, designed against, not assumed.** `Fundamentals` holds 3,813 rows / 215 NASDAQ symbols / **all form 10-K**; `asOf` 2006-09-24..2026-07-03, `releasedAt` 2009-10-27..2026-08-07; median 19 rows/symbol. There is **no** `peRatio`, no market cap, no share count and no quarterly row, so every price-normalized valuation metric is unavailable and was not designed against. Across the frozen 60-name sleeve, 59/60 carry at least one row (XOM carries none, ever) and usable YoY revenue growth at the decision date runs 18/60 (2018-01) → 49/60 (2020-01) → 55–58/60 across the OOS window. Staleness is annual by construction (median 300–345 days), so the variable is used as a slow structural filter and never as a fast signal.
- **The fallback is ADMIT_UNCONDITIONED and it cannot leak.** A name with no usable pair passes the gate untouched. The branch is evaluated from the same `releasedAt <= asOf` read as the value, so a name is "missing" exactly when it was missing to a real decision-maker; and ADMIT (never EXCLUDE) keeps the rule from becoming a covert bet on filing coverage. Total inertness collapses the book onto the comparator, which is precisely what makes the inert-axis test detectable.
- **A mandatory inert-axis falsification, published from the run's own evidence.** `medianWeeklyGatedSkips < 2.0`, or an identical top-5 on ≥90% of decision weeks, kills the hypothesis regardless of CAGR/DSR and must be reported as an inert-axis finding. This is the exact death the exit-only stop lane suffered and it is now a preregistered condition rather than a retrospective observation.
- **It cannot promote, by arithmetic.** At the 108-trial exploratory floor a 2.55-year OOS window needs an annualized Sharpe near 2.9 for DSR > 0.95, which the Sharpe > 3.00 implausibility ceiling makes effectively unreachable. REJECTED is the expected terminal label and is not the question; the only legitimate output is a candidate for a separate sealed, forward-only CONFIRMATORY manifest under QDR-9/QDR-16.
- **QDR-14 fence, disclosed not lifted.** The id must enter `PIT_MEMBERSHIP_REQUIRED_SETUP_IDS` (`src/quant/universe/pointInTimeMembership.ts:136`). Historical membership, delisting lifecycle and independent per-name Sharia evidence do not exist for 2018–2026, so any run of this version is unverified-diagnostic-only and cannot produce a terminal card until the QDR-14 waiver path is satisfied. No gate, threshold, or estimator moves under this record. `halal-fast-momentum-cash-core@v1` is not touched, read, or run.

Revisit when: the inert-axis condition fires (the fundamental family is closed on this book and the next lever must be a different data class, not another fundamental ratio); or the gate demonstrably changes the book AND lifts OOS DSR above 0.894 with the tail cut ≥5pp (a sealed forward CONFIRMATORY lane on this mechanism becomes the correct next preregistration); or a fundamentals vendor with quarterly, price-normalized, PIT-filed metrics lands under QOQ-2, which reopens the metric choice entirely and requires a fresh record.
